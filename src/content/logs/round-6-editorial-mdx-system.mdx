## 작업 전 상태

Log 본문은 18px 글자와 `h2`, 목록 정도만 꾸며져 있었습니다. 제목 단계, 체크박스, 코드, 표, 인용문이 서로 충분히 구분되지 않아 내용이 길어질수록 구조를 빠르게 파악하기 어려웠습니다.

<InputBox label="이번 작업 범위">
  Log와 Project의 MDX 본문 표현, 재사용 블록, 작업 로그 템플릿
</InputBox>

## 참고하고 정한 방향

[우아한형제들 기술블로그](https://techblog.woowahan.com/)와 [토스 테크](https://toss.tech/)의 큰 제목, 짧은 도입, 단계적인 소제목, 여유 있는 본문 흐름을 참고했습니다. 특정 사이트를 복제하지 않고 BUILD & LEARN의 검정·흰색·주황색 디자인을 유지했습니다.

> 긴 글도 제목과 증거 블록만 훑으면 작업 흐름을 이해할 수 있게 만드는 것이 핵심입니다.

## 변경한 내용

### 추가

- `Callout` 안내 블록
- `InputBox` 읽기 전용 정보 블록
- 체크박스와 표를 지원하는 GFM 문법
- 2·3·4단계 제목, 인용, 링크, 인라인 코드, 코드 블록, 표 스타일

### 수정

- Log와 Project가 같은 MDX 컴포넌트와 문법을 사용하도록 통합
- 작업 로그 템플릿에 블록별 작성법과 복사 가능한 예시 추가
- 모바일에서도 코드와 표가 페이지 전체를 밀어내지 않도록 가로 스크롤 범위 제한

### 삭제

- 없음

## 블록은 언제 사용할까

| 블록     | 적합한 내용              | 피해야 할 사용                         |
| -------- | ------------------------ | -------------------------------------- |
| 제목     | 글의 큰 흐름과 세부 단계 | 모든 문장을 제목으로 만들기            |
| 체크박스 | 실제 검증 여부           | 하지 않은 일을 완료로 표시하기         |
| InputBox | 범위, 환경, 핵심 결과    | 긴 본문 전체 넣기                      |
| Callout  | 주의, 성공, 초보자 설명  | 강조할 필요 없는 일반 문장             |
| 코드     | 실제 명령과 구현 예시    | 실행하지 않은 코드를 결과처럼 표현하기 |

<Callout title="초보자 메모" tone="note">
  Markdown은 글의 의미를 정하고 CSS는 그 의미가 눈에 보이게 만듭니다. 예를 들어 `##`는 큰
  부제목이라는 의미이고, 위쪽 굵은 선과 큰 여백은 CSS가 담당합니다.
</Callout>
