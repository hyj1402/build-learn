# BUILD & LEARN 개발 요청 관리 문서

이 문서는 새로운 개발 요청을 받을 때마다 **같은 파일을 계속 수정하는 단일 작업 요청서**입니다. 완료된 작업의 자세한 기록은 `docs/development/DEVELOPMENT_LOG.md`에 누적합니다.

## 현재 작업

### 기본 정보

- 작업 이름: 관리자 방문 로그 간격과 이중 페이지네이션 개선
- 시작일: 2026-09-30
- 상태: 검증 보류
- 참고 화면: `/admin/visits`
- 작업 원칙: 상단 30일 순위와 하단 방문 내역이 각자 페이지를 이동하되 검색 조건과 상대 페이지를 유지한다.

### 요청 배경

방문 로그는 페이지네이션 코드가 있었지만 한 페이지가 30건이라 현재 29건에서는 이동 UI가 숨겨졌습니다. 최근 30일 많이 읽힌 글도 상위 5개에서 잘려 나머지를 확인할 수 없고, 순위 영역과 검색 영역이 여백 없이 붙어 보입니다.

### 추가할 것

- [x] 최근 30일 많이 읽힌 글을 3개씩 보여 주는 소형 이전·다음 페이지 이동
- [x] 현재 방문 내역 페이지 안내

### 수정할 것

- [x] 방문 내역 한 페이지 크기를 30건에서 10건으로 조정
- [x] 순위 영역과 검색 영역 사이 여백 추가

### 삭제할 것

- 없음

### 하지 않을 것

- 방문 로그의 수집 항목·2년 보관 기준 변경
- Supabase 스키마·RLS 변경
- Claude가 작업 중인 Tech Radar 변경 수정

### 완료 조건

- 방문 29건이면 하단 목록이 10건씩 3페이지로 표시됨
- 순위 콘텐츠가 3개를 넘으면 별도 이전·다음 이동이 표시됨
- 한쪽 페이지 이동 시 다른 쪽 페이지와 검색·종류·날짜 조건이 유지됨
- 데스크톱·모바일에서 영역이 겹치거나 가로로 넘치지 않음

### 작업 결과

- 방문 내역은 10건씩 기존 `AdminPagination`으로 이동하고 결과 건수 옆에 현재/전체 페이지를 표시합니다. 현재 29건이면 3페이지가 만들어집니다.
- 최근 30일 많이 읽힌 글은 3개씩 별도 `rankPage`로 이동합니다. 상단 순위와 하단 방문 내역의 페이지 번호, 검색·종류·날짜 조건을 서로 보존합니다.
- 순위 카드와 검색 영역 사이에 전용 여백을 추가하고 소형 이전·다음 UI를 기존 관리자 테마 토큰으로 구성했습니다.
- 변경 파일 ESLint, TypeScript(`--incremental false`), Prettier와 `git diff --check`를 통과했습니다. Next.js 프로덕션 빌드는 실행 중인 개발 서버가 `.next/trace-build`를 사용 중이라 Windows `EPERM`으로 시작 단계에서 중단되어 최종 빌드 검증만 보류했습니다.

### 요청 배경

현재 Log 상세는 큰 그라데이션 제목 영역과 소제목별 파랑·보라·초록·노랑 배경으로 구역을 나눕니다. 사용자는 색을 많이 쓰지 않고, 부드러운 본문 글꼴과 여백·굵기 중심으로 중요한 부분만 강조하는 긴 글 화면을 원합니다.

### 추가할 것

### 수정할 것

- [x] 소제목·인용·코드·표·Callout을 무채색 중심으로 단순화
- [x] 모바일과 다크 모드에서도 같은 읽기 흐름 유지

### 삭제할 것

- [x] Log 상세 제목 영역의 색상 그라데이션과 카드 그림자
- [x] 본문 `h2`마다 순환하는 네 가지 강조색

### 하지 않을 것

- Supabase 데이터·스키마·RLS 변경
- Medium의 로고·아이콘·고유 UI 복제

### 완료 조건

- Log 상세가 약 680~720px의 읽기 열과 일관된 무채색 위계로 표시됨
- 데스크톱·모바일·라이트/다크 모드에서 가로 넘침과 대비 문제가 없음
- `npm run lint`, `npm run type-check`, `npm run format:check`, `npm run build` 통과
- 변경 결과가 누적 개발 로그에 기록됨

### 작업 결과

- Log 상세 전체 폭을 820px, 실제 본문 읽기 열을 680px로 제한하고 제목·요약·발행일·예상 읽기 시간·태그 순서로 정보 위계를 정리했습니다.
- 긴 본문과 요약에는 `Noto Serif KR`을 적용하고 제목·메뉴·소제목에는 기존 `Space Grotesk`를 유지했습니다.
- 제목 영역의 그라데이션·카드 그림자와 `h2` 네 가지 순환색을 제거했습니다. 인용·인라인 코드·표·기본 Callout은 무채색으로 바꾸고, warning·success처럼 의미가 있는 상태색만 남겼습니다.
- 데스크톱 브라우저에서 글 영역 820px·본문 680px, 모바일 브라우저에서 본문 17px·줄간격 32.3px로 표시되는 것을 확인했습니다. 두 화면 모두 가로 넘침과 콘솔 오류가 없었고 키보드 본문 바로가기 링크도 정상 표시됐습니다.
- 다크 모드는 새 스타일이 기존 `--background`, `--foreground`, `--muted`, `--line`, 의미색 변수만 참조하도록 구성해 기존 테마 토큰을 그대로 따릅니다.
- `npm run lint`, `npm run type-check`, `npm run build`를 통과했습니다. 최종 문서 반영 후 `npm run format:check`를 재실행합니다.

## 사용하는 방법

1. 새 요청을 시작할 때 아래의 `현재 작업`을 새 내용으로 교체합니다.
2. 무엇을 추가·수정·삭제하는지 먼저 구분합니다.
3. 작업 전에 현재 문제와 완료 조건을 적습니다.
4. 작업이 끝나면 실제 변경 결과와 검증 명령을 기록합니다.
5. 자세한 과정과 초보자 설명은 `docs/development/DEVELOPMENT_LOG.md`에 날짜별로 추가합니다.
