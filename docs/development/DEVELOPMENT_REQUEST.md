# BUILD & LEARN 개발 요청 관리 문서

이 문서는 새로운 개발 요청을 받을 때마다 **같은 파일을 계속 수정하는 단일 작업 요청서**입니다. 완료된 작업의 자세한 기록은 `docs/development/DEVELOPMENT_LOG.md`에 누적합니다.

## 현재 작업

### 기본 정보

- 작업 이름: Project 상세 댓글 지원
- 시작일: 2026-09-18
- 상태: 완료
- 참고 화면: 공개 Project 상세, `/admin/projects`, `/admin/project-comments`
- 작업 원칙: Log 댓글과 같은 권한·소프트 삭제·관리자 복구 규칙을 Project에도 적용하되, 두 콘텐츠의 댓글 데이터는 별도 테이블로 보관

### 요청 배경

현재 회원 댓글은 Log 상세에만 달 수 있어, 포트폴리오 Project를 본 방문자가 의견을 남길 수 없습니다. 이미 확정한 댓글 권한 규칙을 Project에도 동일하게 적용하고, 관리자가 Project 댓글도 전용 관리 화면에서 확인할 수 있어야 합니다.

### 추가할 것

- [x] `project_comments` 테이블, 인덱스, RLS, 변경 보호 트리거
- [x] 공개 Project 상세의 댓글 목록·작성·수정·소프트 삭제 UI
- [x] `/admin/projects`의 Project별 댓글 수와 `/admin/project-comments` 관리 화면

### 수정할 것

- [x] 기존 댓글 컴포넌트를 콘텐츠 종류를 받는 공용 UI로 정리
- [x] 관리자 댓글 액션이 Log와 Project를 안전하게 구분해 수정·삭제·복구하도록 확장
- [x] 구현 후 원격 RLS 허용·거부 요청, UI, 품질 검사 확인

### 삭제할 것

- 없음

### 하지 않을 것

- 댓글 답글·알림·좋아요 기능
- 일반 회원의 삭제 댓글 복구
- 일반 회원의 타인 댓글 수정·삭제 및 삭제 원문 노출

### 완료 조건

- 공개 Project 상세에서 누구나 활성 댓글을 읽고 로그인한 회원이 댓글을 작성 가능
- 일반 회원은 본인 활성 Project 댓글만 수정·소프트 삭제하고, 관리자는 모든 Project 댓글을 관리·복구 가능
- 일반 공개 Project 상세에는 삭제된 댓글이 보이지 않고, 관리자는 `/admin/project-comments`에서 원문·기록 시각을 확인 가능
- `/admin/projects`에서 Project별 댓글 수를 확인하고 해당 Project 댓글 목록으로 이동 가능
- `npm run lint`, `npm run type-check`, `npm run format:check`, `npm run build` 통과
- Security/Performance Advisor와 비밀값 노출 여부 확인

### 작업 결과

- `project_comments` 테이블과 명시적 Data API 권한, RLS, 소프트 삭제·수정 시각 트리거를 원격 DB에 적용했습니다.
- Project 상세는 기존 댓글 UI를 재사용해 로그인 작성, 본인·관리자 수정/삭제, 삭제 댓글 숨김을 지원합니다.
- `/admin/projects`에 댓글 수·필터 링크를 넣고 `/admin/project-comments`에서 Project 댓글의 원문·기록 시각·수정·삭제·복구를 관리합니다.
- 원격 RLS 테스트에서 타인 수정·물리 삭제·삭제 댓글 조회는 각 0건, 관리자 복구는 1건과 수정 시각 기록을 확인했고 테스트는 롤백했습니다.
- `npm run lint`, `npm run type-check`, `npm run format:check`, `npm run build`를 모두 통과했습니다.

### 추가할 것

- [x] 발행일과 예상 읽기 시간을 한 줄로 보여주는 메타 정보

### 수정할 것

- [x] 소제목·인용·코드·표·Callout을 무채색 중심으로 단순화
- [x] 모바일과 다크 모드에서도 같은 읽기 흐름 유지

### 삭제할 것

- [x] 본문 `h2`마다 순환하는 네 가지 강조색

### 하지 않을 것

- Project 상세와 공개 목록 디자인 변경
- Supabase 데이터·스키마·RLS 변경
- Medium의 로고·아이콘·고유 UI 복제

### 완료 조건

- Log 상세가 약 680~720px의 읽기 열과 일관된 무채색 위계로 표시됨
- 데스크톱·모바일·라이트/다크 모드에서 가로 넘침과 대비 문제가 없음
- `npm run lint`, `npm run type-check`, `npm run format:check`, `npm run build` 통과
- 변경 결과가 누적 개발 로그에 기록됨

### 작업 결과

- Log 상세 전체 폭을 820px, 실제 본문 읽기 열을 680px로 제한하고 제목·요약·발행일·예상 읽기 시간·태그 순서로 정보 위계를 정리했습니다.
- 긴 본문과 요약에는 `Noto Serif KR`을 적용하고 제목·메뉴·소제목에는 기존 `Space Grotesk`를 유지했습니다.
- 제목 영역의 그라데이션·카드 그림자와 `h2` 네 가지 순환색을 제거했습니다. 인용·인라인 코드·표·기본 Callout은 무채색으로 바꾸고, warning·success처럼 의미가 있는 상태색만 남겼습니다.
- 데스크톱 브라우저에서 글 영역 820px·본문 680px, 모바일 브라우저에서 본문 17px·줄간격 32.3px로 표시되는 것을 확인했습니다. 두 화면 모두 가로 넘침과 콘솔 오류가 없었고 키보드 본문 바로가기 링크도 정상 표시됐습니다.
- 다크 모드는 새 스타일이 기존 `--background`, `--foreground`, `--muted`, `--line`, 의미색 변수만 참조하도록 구성해 기존 테마 토큰을 그대로 따릅니다.
- `npm run lint`, `npm run type-check`, `npm run build`를 통과했습니다. 최종 문서 반영 후 `npm run format:check`를 재실행합니다.

## 사용하는 방법

1. 새 요청을 시작할 때 아래의 `현재 작업`을 새 내용으로 교체합니다.
2. 무엇을 추가·수정·삭제하는지 먼저 구분합니다.
3. 작업 전에 현재 문제와 완료 조건을 적습니다.
4. 작업이 끝나면 실제 변경 결과와 검증 명령을 기록합니다.
5. 자세한 과정과 초보자 설명은 `docs/development/DEVELOPMENT_LOG.md`에 날짜별로 추가합니다.
