# BUILD & LEARN 개발 요청 관리 문서

이 문서는 새로운 개발 요청을 받을 때마다 **같은 파일을 계속 수정하는 단일 작업 요청서**입니다. 완료된 작업의 자세한 기록은 `docs/development/DEVELOPMENT_LOG.md`에 누적합니다.

## 현재 작업

### 기본 정보

- 작업 이름: 공개 AI 코멘트 비용·길이 안전장치 보완
- 시작일: 2026-09-22
- 상태: 완료
- 참고 화면: `/admin/logs/[id]/edit`, `/log/[slug]`
- 작업 원칙: 관리자가 검토 후 공개하는 기존 흐름은 유지하고, 외부 AI 호출의 반복 비용과 출력 길이만 서버·화면에서 보완

### 요청 배경

리뷰에서 공개 AI 코멘트는 요청 프롬프트에만 600자 제한을 두고, 생성 버튼을 연속으로 눌러도 서버가 막지 않는 점을 확인했습니다. AI 글쓰기 피드백에는 이미 있는 비용 보호 수준과 맞춰야 합니다.

### 추가할 것

- [x] 관리자별 공개 AI 코멘트 생성 30초 간격 제한
- [x] 화면에서 남은 대기 시간 표시와 버튼 비활성화
- [x] AI가 생성한 초안을 서버에서 600자 이내로 강제

### 수정할 것

- [x] 기존 관리자 권한 확인·검토 후 저장·공개 흐름 유지

### 삭제할 것

- 없음

### 하지 않을 것

- AI 코멘트 DB 컬럼·RLS·공개 범위 변경
- AI가 생성한 내용의 자동 저장 또는 자동 공개
- 실제 Claude API 호출(비용 발생)

### 완료 조건

- 같은 관리자가 30초 안에 공개 코멘트 생성을 다시 요청하면 서버가 거부함
- 화면도 같은 대기 시간을 표시해 불필요한 요청을 막음
- 모델이 긴 답변을 보내도 AI 초안은 600자를 넘지 않음
- `npm run lint`, `npm run type-check`, `npm run format:check`, `npm run build` 통과

### 작업 결과

- 서버 인스턴스 메모리에 관리자별 마지막 생성 시각을 기록하고, 30초 안의 재요청은 API 호출 전에 거부합니다. 서버리스 인스턴스 전체에 공유되는 과금 제한은 아니지만 실수로 연속 클릭하는 경우를 막는 1차 보호입니다.
- 생성 성공 후 화면도 30초를 세어 버튼을 비활성화하고 남은 시간을 표시합니다. 서버 검증을 그대로 대체하지 않고 보조합니다.
- Claude가 프롬프트의 600자 요청을 따르지 않아도 생성 초안은 서버에서 600자 이하로 자릅니다. 관리자가 직접 수정하는 코멘트의 기존 3,000자 저장 한도는 유지합니다.
- DB 마이그레이션·RLS는 변경하지 않았고, Claude API는 비용이 발생하므로 실제 호출하지 않았습니다. 변경 파일 lint·TypeScript(`--incremental false`)·Prettier 검사는 통과했습니다. 일반 `npm run`과 `next build`는 실행 중인 개발 서버가 잠근 `.next` 파일 때문에 이번 세션에서는 다시 실행하지 못했습니다.

- Log 상세가 약 680~720px의 읽기 열과 일관된 무채색 위계로 표시됨
- 데스크톱·모바일·라이트/다크 모드에서 가로 넘침과 대비 문제가 없음

- 변경 결과가 누적 개발 로그에 기록됨

### 작업 결과

- Log 상세 전체 폭을 820px, 실제 본문 읽기 열을 680px로 제한하고 제목·요약·발행일·예상 읽기 시간·태그 순서로 정보 위계를 정리했습니다.
- 긴 본문과 요약에는 `Noto Serif KR`을 적용하고 제목·메뉴·소제목에는 기존 `Space Grotesk`를 유지했습니다.
- 제목 영역의 그라데이션·카드 그림자와 `h2` 네 가지 순환색을 제거했습니다. 인용·인라인 코드·표·기본 Callout은 무채색으로 바꾸고, warning·success처럼 의미가 있는 상태색만 남겼습니다.
- 데스크톱 브라우저에서 글 영역 820px·본문 680px, 모바일 브라우저에서 본문 17px·줄간격 32.3px로 표시되는 것을 확인했습니다. 두 화면 모두 가로 넘침과 콘솔 오류가 없었고 키보드 본문 바로가기 링크도 정상 표시됐습니다.
- 다크 모드는 새 스타일이 기존 `--background`, `--foreground`, `--muted`, `--line`, 의미색 변수만 참조하도록 구성해 기존 테마 토큰을 그대로 따릅니다.
- `npm run lint`, `npm run type-check`, `npm run build`를 통과했습니다. 최종 문서 반영 후 `npm run format:check`를 재실행합니다.

1. 새 요청을 시작할 때 아래의 `현재 작업`을 새 내용으로 교체합니다.

3. 작업 전에 현재 문제와 완료 조건을 적습니다.
4. 작업이 끝나면 실제 변경 결과와 검증 명령을 기록합니다.
