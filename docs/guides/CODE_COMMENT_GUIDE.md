# BUILD & LEARN 코드 주석 가이드

이 문서는 Next.js나 TypeScript를 처음 보는 사람도 코드의 역할과 흐름을 따라갈 수 있도록 주석을 작성하는 기준입니다.

## 반드시 설명할 것

- 파일 또는 컴포넌트가 화면에서 맡는 역할
- 함수가 받는 값, 처리 과정, 반환 결과
- URL, 필터, 정렬, 공개 여부처럼 화면 결과를 바꾸는 규칙
- Server Component와 Client Component를 나눈 이유
- metadata, sitemap, 정적 경로처럼 Next.js가 자동 실행하는 함수
- 접근성, 보안, 성능 때문에 선택한 속성
- 단순해 보이지만 제거하면 과거 버그가 다시 생기는 코드

## 줄마다 설명하지 않는 이유

```ts
// count에 1을 더합니다.
count += 1;
```

코드와 같은 말을 반복하는 주석은 읽을 양만 늘립니다. 아래처럼 목적과 이유를 설명합니다.

```ts
// 같은 날짜의 글도 작업 순서가 일정하도록 두 번째 정렬 기준을 적용합니다.
return (b.order ?? 0) - (a.order ?? 0);
```

## 새 기능 작성 순서

1. 파일 위나 주요 함수 위에 역할을 한 문장으로 적습니다.
2. 사용자가 입력하는 값이나 URL 값은 어디서 검증하는지 적습니다.
3. Next.js가 자동 호출하는 함수라면 호출 시점을 설명합니다.
4. 보안·접근성·성능 속성에는 선택 이유를 적습니다.
5. 구현 후 주석이 실제 코드와 같은지 다시 확인합니다.

## 주석이 오래되지 않게 관리하기

기능을 변경하면 관련 주석도 같은 작업에서 수정합니다. 코드와 다른 주석은 주석이 없는 것보다 위험하므로, 설명이 더 이상 맞지 않으면 즉시 고치거나 삭제합니다.
